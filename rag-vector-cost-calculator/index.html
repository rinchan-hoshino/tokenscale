Mathematical model and engineering assumptions

Chunking & quantized HNSW footprint

ChunksPerDoc = ceil(AvgDocTokens / (ChunkSize * (1 - Overlap)))
Vectors = Docs * ChunksPerDoc
IndexRAM_GiB = Vectors * (Dim * B_quant + 256) * HNSW_overhead / 1024^3

Includes 256 bytes per vector for document IDs and filterable metadata payloads, multiplied by each engine's HNSW graph overhead factor (1.20x–1.65x).

Engineering FAQ

How much RAM does Scalar (INT8) or Binary (1-bit) quantization save?

Standard FP32 embeddings store 4 bytes per dimension (6 KB per 1536-d vector). Scalar INT8 quantization cuts raw vector memory by 4x with less than 1% recall drop, while Binary 1-bit quantization compresses vectors by up to 32x—often paired with rescoring the top-100 candidates.

Why does HNSW index RAM exceed raw vector size by 1.5x to 1.65x?

Hierarchical Navigable Small World (HNSW) graphs store bi-directional neighbor pointer lists across multiple layers alongside payload metadata and filter indexes. Sizing RAM solely on raw float bytes causes severe OOM crashes or disk thrashing.

When is Pinecone Serverless cheaper than dedicated RAM clusters?

At low-to-moderate query volume (under ~15–25 sustained QPS) with large vector corpora, serverless object-backed storage ($0.33/GB) avoids paying for idle 24/7 RAM nodes. Above ~100 sustained QPS, self-hosted pgvector or Qdrant Cloud clusters usually win on unit economics.

Why does chunk overlap affect total vector database cost?

Overlap reduces the effective stride between chunks. A 25% overlap increases total chunk count—and therefore embedding spend, HNSW RAM, and query latency—by 33% compared to zero overlap.
